Contributing to [AliXiA's Reaper Scripts]
First off, thank you for considering contributing to [AliXiA's Reaper Scripts]! It's people like you that make the open-source community such an amazing place to learn, inspire, and create.
Please take a moment to review this document before submitting your first contribution. Following these guidelines helps us process your issues and pull requests much faster.
Code of Conduct
By participating in this project, you agree to abide by our Code of Conduct. Please report any unacceptable behavior to [alicia4prez@gmail.com].
How Can I Contribute?
Reporting Bugs
• Check existing issues: Before opening a new issue, please search the repository to ensure the bug hasn't already been reported.
• Use the template: Fill out the bug report template completely when creating a new issue.
• Be specific: Include a clear title, steps to reproduce the bug, expected vs. actual behavior, and details about your environment (OS, runtime version, etc.).
Suggesting Enhancements
• Check existing requests: Ensure your idea hasn't already been suggested or implemented.
• Explain the value: Describe the problem you are trying to solve and why this feature would be useful to most users.
• Keep it focused: Stick to one feature request per issue.
Submitting a Pull Request (PR)
1. Fork the repository to your own GitHub account.
2. Clone the fork locally to your machine.
3. Create a new branch off the main branch (e.g., git checkout -b feature/my-new-feature or bugfix/fix-issue-123).
4. Make your changes. Adhere to the existing code style and formatting.
5. Write tests for your changes if applicable.
6. Commit your changes with clear, descriptive commit messages.
7. Push to your fork and submit a pull request back to our main repository.
8. Link the relevant issue in your pull request description (e.g., "Closes #123").
Style Guides & Coding Standards
Code Style
• Follow the standard style guides for [lua].
• Ensure all code formatting tools or linters pass before committing (npm run lint, flake8, etc.).
Commit Messages
• Use the imperative mood in the subject line (e.g., "Fix bug" rather than "Fixed bug" or "Fixes bug").
• Reference issue tracking numbers where appropriate.
Getting Help
If you have questions or get stuck, feel free to:
• Ask in the comments of your GitHub issue or pull request.
• Reach out in our coming soon.
